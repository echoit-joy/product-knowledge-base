## 이번 버전에서 달라진 것

### 1. `/qa-gen` — QA TC만 따로 만들 수 있어요

- GitHub 프로젝트가 없어도 로컬 기능정의서 XLSX만 있으면 QA TC를 만들 수 있습니다.
- GitHub KB가 있으면 참고하고, 없으면 로컬 XLSX 기준으로 진행합니다.
- `workspace/` 밖 XLSX 파일도 경로만 알려주면 읽을 수 있습니다.
- 원본 기능정의서 XLSX는 읽기 전용으로만 사용하므로 기존 파일이 망가지지 않습니다.

### 2. 산출물 받는 방식을 시작할 때 고를 수 있어요

`/spec-flow`, `/project-flow`, `/qa-gen` 시작 직후 Step 0-DM에서 아래 3가지 중 하나를 선택합니다.

| 선택 | 언제 쓰면 좋은가요? | 결과 |
|------|----------------------|------|
| `xlsx_only` | 기존처럼 파일로 확인하고 싶을 때 | XLSX만 생성합니다. 기본값입니다. |
| `gsheets_only` | 팀 공유용 Google Sheets에만 남기고 싶을 때 | 내부 검증용 임시 XLSX로 검사한 뒤 Google Sheets에만 씁니다. |
| `xlsx_and_gsheets` | 파일도 받고 Google Sheets에도 남기고 싶을 때 | XLSX를 생성하고, 검증 통과 후 Google Sheets에도 씁니다. |

### 3. Google Sheets writeback이 더 편하고 안정적이에요

- QA TC를 Google Sheets에 쓸 때는 **기본 탭 하나에 전체 TC를 합쳐서** 기록합니다.
- URL만 알려줘도 화면별로 탭을 자동으로 나누거나 생성하지 않습니다.
  - 예: "목표매출관리" 화면과 "영업현황" 화면 TC가 있어도 `QA_TC` 탭 하나에 합쳐서 기록합니다.
- 탭 이름을 따로 지정하지 않으면 `QA_TC`, 시작 셀을 지정하지 않으면 `A1`로 처리합니다.
- No 컬럼은 여러 시트를 합친 뒤 1부터 다시 번호를 매깁니다.
- dry-run 미리보기에서 원본 시트 목록, 병합 행 수, 기록 탭 이름을 보여줍니다.
- 기능정의서가 여러 시트로 나뉘어 있어도 `기능정의_` 시트를 모아 Google Sheets에 씁니다.
- Google Sheets에 쓴 뒤 실제 행/열 범위를 다시 읽어 검증합니다.
- 팀원은 Google Cloud OAuth client를 직접 만들 필요가 없습니다. 관리자가 공유한 `client_secret` JSON을 한 번 등록하면 됩니다.

### 4. 기능정의서에 X 버튼이 있으면 QA TC에 그대로 담아요

- `/qa-gen`은 이미 작성된 기능정의서를 기반으로 QA TC를 만드는 흐름입니다.
- source 기능정의서 Action/Property/Note에 X 버튼 클릭·닫힘이 적혀 있으면, harness 내부 정책과 관계없이 해당 QA TC를 생성합니다.
- "harness 정책상 X 버튼 TC 금지인데 제외할까요?" 같은 불필요한 재확인을 하지 않습니다.
- `qa_auditor`에 `--source-spec` 옵션을 주면, source에 명시된 X 버튼 TC는 FAIL 대신 WARN으로 처리됩니다.
  - source에 없는 X 버튼 TC를 AI가 임의로 생성한 경우: 기존처럼 FAIL.

### 5. AI가 놓치기 쉬운 기획 품질 이슈를 더 잘 잡아요

- 질문이 많을 때 3개만 묻고 바로 Draft로 넘어가는 문제를 방지합니다.
- 삭제된 기능을 너무 넓게 해석해 정상 기능까지 막는 문제를 줄였습니다.
- 공통 UI 용어는 `global/glossary.md`를 참고합니다.
- Action 컬럼에는 동작만 쓰도록 검증합니다. `(변경 사항 미적용)` 같은 결과 설명이 들어가면 FAIL 처리합니다.
- X 버튼은 source 기능정의서에 명시된 경우에만 QA TC에 적습니다.

### 6. 실행 중 헷갈리던 부분을 정리했어요
