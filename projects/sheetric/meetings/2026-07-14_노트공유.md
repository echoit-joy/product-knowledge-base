# 2026-07-14 노트공유 회의록

## 목적

Sheetric 2차 기능 범위 중 노트 공유와 공유 드라이브 관련 요구사항을 정리한다.

이 문서는 회의록이며, 확정 decision 문서가 아니다. 확정된 정책은 별도 `decisions/` 문서로 분리해 기록한다.

## 관련 자료

- `Sheetric 프로젝트 - 기능정의_2차.tsv`
- Figma 공유/소유권 이전 메일 문안

## 정리된 내용

### 1. 공유 기본 방향

- 2차 공유 기능은 읽기 전용 공유를 우선 범위로 한다.
- 공유받은 문서와 폴더는 수정할 수 없다.
- 편집 권한과 실시간 공동 편집은 이후 단계에서 별도 검토한다.
- 공유받은 문서를 열람하는 경우 노트 상세 상단에 `읽기 전용` 뱃지를 표시한다.
- 공유받은 문서에서는 편집 관련 UI를 비활성화한다.

### 2. 공유 범위와 접근 정책

- `불특정 사용자 전체 공유`는 현재 링크 공유와 같은 의미로 본다.
- 링크 공유 문서는 로그인 없이 접근 가능하며, 읽기 전용으로만 제공한다.
- 공개 링크 공유 URL과 편집 URL은 별개다.
- 읽기 전용 공유 URL과 특정 사용자 공유 진입 URL도 별도 정책으로 다룬다.
- 기존 `공유 링크 별도 읽기 전용 URL` 결정은 유지한다.
- 기존 `폴더 공유 제외` 결정은 `상태: 삭제`이므로, 이번 2차 범위에서는 폴더 공유를 다시 포함해 검토한다.

### 3. 특정 사용자 공유

- 특정 사용자 공유는 회원가입된 이메일만 가능하다.
- 모달에서 이메일을 입력하고 Enter를 누르면 이메일이 X 버튼이 있는 chip 형태로 전환된다.
- 가입되지 않은 이메일은 초대 플로우로 넘기지 않는다.
- 가입되지 않은 이메일 추가 시도 시 실패 토스트를 노출한다.
  - 기능정의서 초안 L10N: `toast.emailnotregistered.error`
- 이미 공유된 사용자는 검색 결과에서 제외한다.
- 공유 모달에서 사용자를 추가하거나 삭제해도 즉시 서버에 반영하지 않는다.
- `[확인]`을 눌러야 사용자 추가/삭제가 실제 반영된다.
- `[취소]` 또는 모달 닫기 시 모달에서 변경한 추가/삭제 내역은 폐기된다.
- 특정 사용자 공유는 문서와 폴더 모두 가능하다.
- 폴더 공유 시 하위 문서와 하위 폴더까지 공유 범위에 포함한다.

### 4. 공유 드라이브 표시 방식

- 이메일 초대 방식으로 공유받은 항목은 `공유 드라이브` 메뉴에 표시한다.
- 공유 드라이브에는 공유받은 문서와 폴더가 표시된다.
- 공유 드라이브 목록 테이블 컬럼은 아래 방향으로 정리한다.
  - 체크박스
  - 즐겨찾기
  - 이름
  - 소유자
  - 크기
  - 공유일
  - 수정일
- 기본 정렬은 수정일 기준으로 한다.
- 공유받은 항목이 없으면 빈 상태 문구를 노출한다.
  - 기능정의서 초안 L10N: `status.shareddrive.empty.desc`
- 공유 드라이브 트리뷰는 우선 편집 불가로 개발한다.
- 트리뷰에서는 폴더 펼침, 접힘, 하위 폴더 진입만 가능하다.
- 이름 변경, 이동 등 편집성 기능은 제공하지 않는다.
- 업데이트 표시와 확인 처리 기능은 이번 범위에서 스펙아웃한다.

### 5. 공유 드라이브 컨텍스트 메뉴

- 공유 드라이브에서는 생성, 업로드, 이동, 이름 변경 등 소유자 편집 액션을 숨기거나 제공하지 않는다.
- 공유 드라이브 항목 컨텍스트 메뉴에서 허용할 액션은 아래와 같다.
  - 공유
  - 즐겨찾기
  - 다운로드
  - 태그 관리
  - 속성
  - 공유 목록에서 제거
- 빈 영역 컨텍스트 메뉴에서는 새 폴더, 새 노트 등 생성 관련 메뉴를 숨긴다.
- 빈 영역 컨텍스트 메뉴에는 정렬 기준 변경, 보기 옵션 등 조회 관련 메뉴만 노출한다.
- `공유 목록에서 제거`를 실행하면 본인의 접근 권한을 제거하고 공유 드라이브 목록에서 즉시 제거한다.
- 제거 성공/실패 토스트를 노출한다.
  - 기능정의서 초안 L10N: `toast.sharingleft.success`
  - 기능정의서 초안 L10N: `toast.sharingleft.error`
- 공유 목록에서 제거하면 소유자 쪽 공유 모달의 공유 대상 리스트에서도 해당 사용자가 함께 제거되어야 한다.

### 6. 공유 모달

- 노트 상세의 기존 링크 복사 진입점은 공유 모달 오픈 진입점으로 변경한다.
- 공유 모달 타이틀은 `공유`로 표시한다.
- 소유자 본인 행은 `소유자` 텍스트를 고정 표시하고 편집할 수 없다.
- 소유자가 아닌 공유 대상 행에는 소유자에게만 더보기 메뉴를 노출한다.
- 일반 공유 대상의 더보기 메뉴에는 아래 항목을 제공한다.
  - 소유권 이전
  - 삭제
- 소유권 이전 요청 대기 중인 대상자의 더보기 메뉴에는 아래 항목을 제공한다.
  - 소유권 이전 요청됨
  - 이전 요청 취소
  - 삭제
- 링크 복사 성공 시 완료 토스트를 노출한다.
  - 기능정의서 초안 L10N: `toast.linkcopied.success`

### 7. 소유권 이전과 삭제

- 내가 만든 문서 또는 폴더를 다른 사람에게 소유권 이전할 수 있어야 한다.
- 소유권 이전 후 기존 소유자는 일반 공유자로 강등된다.
- 폴더 소유권 이전 시 하위 문서와 하위 폴더까지 함께 이전한다.
- 소유권 이전 요청 성공 시 대상자에게 이메일을 발송한다.
  - 기능정의서 초안 L10N: `toast.ownershiptransferrequested.success`
- 소유권 이전 요청 실패 시 실패 토스트를 노출한다.
  - 기능정의서 초안 L10N: `toast.ownershiptransferrequest.error`
- 소유권 이전 요청 취소 성공/실패 토스트를 노출한다.
  - 기능정의서 초안 L10N: `toast.ownershiptransfercanceled.success`
  - 기능정의서 초안 L10N: `toast.ownershiptransfercancel.error`
- 소유자가 공유 중인 문서 또는 폴더를 삭제하면 공유받은 사용자의 접근은 막힌다.
- 공유 중인 항목 삭제 시 소유권 이전을 유도하지 않고 경고 모달만 노출한다.
- 삭제 확인 시 문서 또는 폴더 삭제와 전체 공유 해제를 함께 처리한다.
  - 기능정의서 초안 L10N: `status.deletewithshare.notice.desc`

### 8. 태그와 즐겨찾기

- 공유받은 항목에도 태그 기능을 사용할 수 있다.
- 공유받은 항목에 붙인 태그는 개인 태그다.
- 공유받은 항목을 즐겨찾기하면 내 즐겨찾기 목록에서만 보인다.
- 즐겨찾기 목록에서 공유받은 항목은 이름 옆에 공유 아이콘으로 구분한다.
- 즐겨찾기 목록의 소유자 컬럼은 본인 소유는 `나`, 타인 소유는 소유자 이름으로 표시한다.

### 9. 이메일 알림

- 초대 공유 시 이메일로 공유 내용을 알린다.
- 폴더 공유 알림 제목은 `'{note_title}' 폴더 공유 알림`으로 한다.
- 노트 공유 알림 제목은 `'{note_title}' 노트 공유 알림`으로 한다.
- 소유권 이전 요청 메일 제목은 `'{note_title}' 노트 소유권 이전 요청`으로 한다.
- 메일 본문은 Figma에 기재된 문안을 따른다.
- 발신자 정보는 메일 본문에 포함된 기준을 따른다.
- 공유 해제 시 이메일 알림은 보내지 않는다.
- 소유권 이전 요청 시 이메일 알림은 보낸다.
- 업데이트 발생 시 이메일 알림은 보내지 않는다.

  - 빈 상태
  - 폴더 트리
  - 행 컨텍스트 메뉴

  - 공유 목록에서 제거 확인 모달
- `공유 모달`
  - 이메일 검색 입력 필드
  - 공유 대상 리스트

  - 링크 복사
  - 취소/확인 버튼

  - 요청 성공/실패 토스트

  - 취소 성공/실패 토스트

  - 공유 아이콘

  - 공유 항목 표시
- `삭제 확인 모달`
  - 공유 중 항목 삭제 경고

## 추가 논의 필요

### 공개 링크와 특정 사용자 링크의 구분

- 회의 정리상 공개 링크 공유는 로그인 없이 읽기 전용 접근이 가능하다.
- 기능정의서 초안의 `share_02_07`은 초대되지 않은 사용자가 열람하면 접근 오류 토스트를 노출한다고 되어 있어, 공개 링크 공유와 특정 사용자 공유 링크가 섞여 보일 수 있다.
- 공유 모달 안에서 복사되는 링크가 공개 읽기 전용 URL인지, 특정 사용자 전용 URL인지 구분이 필요하다.
- 공개 링크 공유 ON/OFF, 링크 재생성, 링크 폐기 기능이 필요한지 결정이 필요하다.

### 특정 사용자 공유와 공개 링크 공유가 동시에 걸린 경우

- 특정 사용자 공유를 해제해도 공개 링크 공유가 켜져 있으면 해당 사용자가 공개 링크로 계속 접근할 수 있는지 정책이 필요하다.
- `공유 목록에서 제거`가 특정 사용자 권한만 제거하는지, 공개 링크 접근에도 영향을 주는지 구분이 필요하다.

### 소유권 이전 수락/거절 플로우

- 기능정의서 초안은 소유권 이전 `요청`과 `요청 취소`까지 정의되어 있다.
- 대상자가 소유권 이전 요청을 수락하거나 거절하는 화면, 진입점, 알림, 만료 정책은 아직 정리되지 않았다.
- 대상자가 요청을 수락하기 전까지 기존 소유자 권한은 유지되는 것으로 보이지만, 수락 이후 실제 전환 시점과 실패 처리 정의가 필요하다.

### 폴더 공유 권한 전파 엣지케이스

- 폴더 공유 시 기존 하위 문서와 하위 폴더까지 포함하는 것은 정리되었다.
- 공유 이후 새로 생성되는 하위 문서와 하위 폴더도 자동 공유되는지 결정이 필요하다.
- 공유 폴더 안팎으로 문서나 하위 폴더를 이동할 때 권한이 어떻게 바뀌는지 결정이 필요하다.
- 하위 항목에 별도 공유 권한이 이미 있는 경우, 폴더 공유 권한과의 우선순위가 필요하다.

### 공유 드라이브 메뉴 라벨

- 정리된 액션명은 `공유 목록에서 제거`다.
- 기능정의서 초안의 행 컨텍스트 메뉴에는 `삭제`로 표기된 부분이 있어, 실제 UI 라벨을 `삭제`로 둘지 `공유 목록에서 제거`로 둘지 최종 확정이 필요하다.
- 공유받은 항목에서 `다운로드`를 허용하는 것은 정리되었지만, 공개 링크 접근자와 특정 사용자 공유 접근자 모두에게 다운로드를 허용할지 구분이 필요하다.

### 접근 권한 상실 후 개인 데이터 처리

- 공유 해제 또는 원본 삭제로 접근 권한이 사라졌을 때, 개인 태그와 즐겨찾기 기록을 즉시 삭제할지 보관할지 결정이 필요하다.
- 공유 드라이브 목록에서는 즉시 제거되지만, 즐겨찾기 목록과 태그 필터에 남은 참조를 어떻게 정리할지 정책이 필요하다.

### 이메일 링크 정책

- 메일 제목과 본문 기준은 정리되었다.
- 초대 메일과 소유권 이전 요청 메일의 링크 만료 여부, 만료 시간, 만료 후 화면 문구는 아직 결정이 필요하다.

## 후속 작업 제안

- 위 내용을 기준으로 `/spec-flow`를 실행하기 전에 `추가 논의 필요` 항목을 먼저 정리한다.
- 확정된 정책은 별도 `decisions/` 문서로 분리한다.
- 기능 정의 시 `공유 드라이브`, `공유 모달`, `소유권 이전`, `읽기 전용 표시`, `공유 중 삭제 경고`를 화면 단위로 분리해 작성한다.
- 공유 관련 기능은 읽기 전용 2차 범위와 이후 편집 권한 범위를 명확히 나누어 작성한다.
