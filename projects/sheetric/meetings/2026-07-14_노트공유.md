# 2026-07-14 노트공유 회의록

## 목적

Sheetric 2차 기능 범위 중 노트 공유와 공유 드라이브 관련 요구사항을 정리한다.

이 문서는 회의록이며, 확정 decision 문서가 아니다. 확정된 정책은 별도 `decisions/` 문서로 분리해 기록한다.

## 관련 자료

- `Sheetric 프로젝트 - 기능정의_2차-2.tsv`
- `Sheetric 프로젝트 - L10N.tsv`
- Figma 공유/소유권 이전 메일 문안

## 정리된 내용

### 1. 공유 기본 방향

- 2차 공유 기능은 읽기 전용 공유를 우선 범위로 한다.
- 공유받은 문서와 폴더는 수정할 수 없다.
- 편집 권한과 실시간 공동 편집은 이후 단계에서 별도 검토한다.
- 공유받은 문서를 열람하는 경우 노트 상세 상단에 `읽기 전용` 뱃지를 표시한다.
- 공유받은 문서에서는 편집 관련 UI를 비활성화한다.

### 2. 공유 범위와 접근 정책

- 공개 링크 공유는 제공하지 않는다.
- 공유 대상자는 반드시 가입 및 로그인된 사용자여야 한다.
- 노트가 열린 상태의 URL과 공유를 통해 접근하는 URL은 서로 다르다.
- 노트가 열린 상태의 일반 URL로 타인이 접근하면 기존처럼 `잘못된 접근입니다` 토스트를 노출한다.
  - 기능정의서/L10N: `toast.wrongapproach.error`
- 공유 모달에서 복사되는 링크도 공개 링크가 아니라 권한이 있는 사용자 접근을 전제로 한다.
- 초대되지 않았거나 권한이 없는 사용자가 공유 URL에 접근하면 접근 오류 토스트를 노출한다.
- 공개 링크 ON/OFF, 공개 링크 재생성, 공개 링크 폐기 기능은 이번 범위의 논의 대상이 아니다.
- 기존 `공유 링크 별도 읽기 전용 URL` 결정 중 "편집 URL과 공유 URL을 분리한다"는 방향은 유지하되, 접근 대상은 로그인된 권한 보유 사용자로 제한한다.
- 기존 `폴더 공유 제외` 결정은 `상태: 삭제`이므로, 이번 2차 범위에서는 폴더 공유를 포함해 검토한다.

### 3. 특정 사용자 공유

- 특정 사용자 공유는 회원가입된 이메일만 가능하다.
- 모달에서 이메일을 입력하고 Enter 또는 검색 결과 선택을 하면 유효성 검사를 수행한다.
- 유효성 검사를 통과한 이메일은 X 버튼이 있는 chip 형태로 전환된다.
- 가입되지 않은 이메일은 초대 플로우로 넘기지 않는다.
- 가입되지 않은 이메일 추가 시도 시 실패 토스트를 노출한다.
  - 기능정의서/L10N: `toast.emailnotregistered.error`
- 본인 이메일은 공유 대상으로 추가할 수 없다.
  - 기능정의서/L10N: `toast.selfinvite.error`
- 이미 공유된 사용자는 검색 결과에서 제외한다.
- chip의 X 버튼을 클릭하면 API 호출 없이 전송 전 chip만 제거한다.
- `[초대]` 버튼은 chip이 1개 이상 있을 때만 활성화한다.
- `[초대]` 클릭 시 현재 남아있는 모든 chip을 공유 대상 추가 API로 일괄 요청한다.
- 전체 성공 시 공유 대상 리스트에 전원 추가하고 chip을 초기화한다.
  - 기능정의서/L10N: `toast.shareadded.success`
- 일부 실패 시 성공한 이메일은 리스트에 반영하고 실패한 이메일은 chip으로 남긴다.
  - 기능정의서/L10N: `toast.shareadd.error`
- 폴더 공유 시 해당 사용자에게 기존 하위 문서와 하위 폴더까지 동일하게 상속한다.
- 공유 이후 해당 폴더 안에 새로 생성되는 하위 문서와 하위 폴더도 자동 공유한다.
- 추가된 사용자의 공유 드라이브 테이블에 노트 또는 폴더가 즉시 추가된다.

### 4. 공유 드라이브 표시 방식

- 이메일 초대 방식으로 공유받은 항목은 `공유 드라이브` 메뉴에 표시한다.
- 공유 드라이브에는 공유받은 문서와 폴더가 표시된다.
- 공유 드라이브 목록 테이블 컬럼은 아래 방향으로 정리한다.
  - 체크박스
  - 즐겨찾기
  - 이름
  - 소유자
  - 크기
  - 공유일
  - 수정일
- 기본 정렬은 수정일 기준으로 한다.
- 공유받은 항목이 없으면 빈 상태 문구를 노출한다.
  - 기능정의서/L10N: `status.shareddrive.desc`
- 공유 드라이브 트리뷰는 우선 편집 불가로 개발한다.
- 트리뷰에서는 폴더 펼침, 접힘, 하위 폴더 진입만 가능하다.
- 공유 드라이브에서 내 노트 또는 폴더를 이동하는 기능은 제공하지 않는다.
- 공유 드라이브 항목을 내 드라이브나 다른 폴더로 이동하는 기능도 제공하지 않는다.
- 이름 변경, 이동 등 편집성 기능은 제공하지 않는다.
- 업데이트 표시와 확인 처리 기능은 이번 범위에서 스펙아웃한다.

### 5. 공유 드라이브 컨텍스트 메뉴

- 공유 드라이브에서는 생성, 업로드, 이동, 이름 변경 등 소유자 편집 액션을 숨기거나 제공하지 않는다.
- 공유 드라이브 항목 컨텍스트 메뉴에서 허용할 액션은 아래와 같다.
  - 공유
  - 즐겨찾기
  - 다운로드
  - 태그 관리
  - 속성
  - 공유 목록에서 제거
- 공유 액션은 소유자와 초대된 사용자 모두에게 노출한다.
- 초대된 사용자도 다른 사용자를 추가하거나 삭제할 수 있다.
- 단, 소유권 이전은 소유자 전용 액션이다.
- 다운로드는 권한이 있는 로그인 사용자에게만 허용한다.
- 공개 링크 접근자는 없으므로 공개 링크 접근자의 다운로드 권한은 별도 논의 대상이 아니다.
- `공유 목록에서 제거`를 실행하면 본인의 접근 권한을 제거하고 공유 드라이브 목록에서 즉시 제거한다.
- 제거 성공/실패 토스트를 노출한다.
  - 기능정의서/L10N: `toast.sharingleft.success`
  - 기능정의서/L10N: `toast.sharingleft.error`
- 공유 목록에서 제거하면 소유자 쪽 공유 모달의 공유 대상 리스트에서도 해당 사용자가 함께 제거되어야 한다.

### 6. 공유 모달

- 노트 상세의 기존 링크 복사 진입점은 공유 모달 오픈 진입점으로 변경한다.
- 공유 모달 타이틀은 `공유`로 표시한다.
- 소유자 본인 행은 `소유자` 텍스트를 고정 표시하고 편집할 수 없다.
- 공유 대상 행에는 더보기 메뉴를 노출한다.
- 더보기 메뉴의 내용은 보는 사람이 소유자인지 초대된 사용자인지에 따라 다르다.
- 소유자가 일반 공유 대상 행을 볼 때 제공하는 메뉴는 아래와 같다.
  - 소유권 이전
  - 삭제 또는 공유 해제
- 초대된 사용자가 일반 공유 대상 행을 볼 때 제공하는 메뉴는 아래와 같다.
  - 삭제 또는 공유 해제
- 소유권 이전 요청 대기 중인 대상자의 더보기 메뉴는 소유자에게만 대기 상태를 노출한다.
- 공유 모달에는 전체 저장용 확인 버튼과 취소 버튼을 제공하지 않는다.
- 사용자 추가, 공유 해제, 소유권 이전 요청 등은 각 액션 실행 시 즉시 저장된다.
- 모달 닫기는 저장 또는 취소 역할을 하지 않는다.
- 모달을 닫아도 이미 성공한 변경사항은 유지된다.
- 링크 복사 성공 시 완료 토스트를 노출한다.
  - 기능정의서/L10N: `toast.linkcopied.success`

### 7. 공유 대상 삭제 또는 공유 해제

- 공유 대상 삭제는 원본 문서 또는 폴더 삭제가 아니라 해당 사용자의 공유 권한 제거를 의미한다.
- 공유 대상 삭제 메뉴를 클릭하면 사용자 삭제 확인 모달을 노출한다.
- 확인 시 공유 대상 삭제 API를 실행한다.
- 성공 시 공유 대상 리스트에서 해당 사용자를 즉시 제거한다.
  - 기능정의서/L10N: `toast.usershareremoved.success`
- 실패 시 기존 공유 상태를 유지한다.
  - 기능정의서/L10N: `toast.usershareremove.error`
- 공유 해제 성공 시 해당 사용자의 공유 드라이브 목록에서도 항목을 즉시 제거한다.
- 공유 해제 또는 원본 삭제로 접근 권한이 사라지면 개인 태그와 즐겨찾기 기록도 즉시 삭제한다.
- 즐겨찾기 목록과 태그 필터에 남은 참조도 즉시 제거한다.

### 8. 소유권 이전과 삭제

- 내가 만든 문서 또는 폴더를 다른 사람에게 소유권 이전할 수 있어야 한다.
- 소유권 이전 요청 성공 시 대상자에게 이메일을 발송한다.
  - 기능정의서/L10N: `toast.ownershiptransferrequested.success`
- 소유권 이전 요청 실패 시 실패 토스트를 노출한다.
  - 기능정의서/L10N: `toast.ownershiptransferrequest.error`
- 소유권 이전 요청 취소 성공/실패 토스트를 노출한다.
  - 기능정의서/L10N: `toast.ownershiptransfercanceled.success`
  - 기능정의서/L10N: `toast.ownershiptransfercancel.error`
- 메일에는 `확인하기` 버튼을 포함하며, 클릭 시 해당 노트 상세 화면으로 이동한다.
- 실제 수락/거절 처리는 메일 링크 자체가 아니라 노트 상세 화면에 자동으로 뜨는 모달에서 이루어진다.
- 대상자가 노트 상세 화면에 진입했을 때 대기 중인 소유권 이전 요청이 있으면 응답 모달을 자동 오픈한다.
- 대상자가 수락하면 수락과 동시에 소유권이 전환된다.
  - 기능정의서/L10N: `toast.ownershiptransferaccepted.success`
  - 기능정의서/L10N: `toast.ownershiptransferaccept.error`
- 소유권 이전 후 기존 소유자는 일반 공유자로 강등된다.
- 대상자가 거절하면 기존 소유자에게 거절 안내 메일을 발송한다.
  - 기능정의서/L10N: `toast.ownershiptransferdeclined.success`
  - 기능정의서/L10N: `toast.ownershiptransferdecline.error`
- 폴더 소유권 이전 시 하위 문서와 하위 폴더까지 함께 이전한다.
- 소유자가 공유 중인 문서 또는 폴더를 삭제하면 공유받은 사용자의 접근은 막힌다.
- 공유 중인 항목 삭제 시 소유권 이전을 유도하지 않고 경고 모달만 노출한다.
- 삭제 확인 시 문서 또는 폴더 삭제와 전체 공유 해제를 함께 처리한다.

### 9. 태그와 즐겨찾기

- 공유받은 항목에도 태그 기능을 사용할 수 있다.
- 공유받은 항목에 붙인 태그는 개인 태그다.
- 공유받은 항목을 즐겨찾기하면 내 즐겨찾기 목록에서만 보인다.
- 즐겨찾기 목록에서 내가 공유했거나 공유받은 항목은 이름 옆에 공유 아이콘으로 구분한다.
- 즐겨찾기 목록의 소유자 컬럼은 본인 소유는 `나`, 타인 소유는 소유자 이름으로 표시한다.
- 내 드라이브에서 내가 다른 사용자에게 공유한 항목도 이름 옆에 공유 아이콘을 표시한다.

### 10. 이메일 알림

- 초대 공유 시 이메일로 공유 내용을 알린다.
- 폴더 공유 알림 제목은 `'{note_title}' 폴더 공유 알림`으로 한다.
- 노트 공유 알림 제목은 `'{note_title}' 노트 공유 알림`으로 한다.
- 소유권 이전 요청 메일 제목은 `'{note_title}' 노트 소유권 이전 요청`으로 한다.
- 메일 본문은 Figma에 기재된 문안을 따른다.
- 발신자 정보는 메일 본문에 포함된 기준을 따른다.
- 공유 해제 시 이메일 알림은 보내지 않는다.
- 소유권 이전 요청 시 이메일 알림은 보낸다.
- 소유권 이전 거절 시 기존 소유자에게 거절 안내 메일을 보낸다.
- 업데이트 발생 시 이메일 알림은 보내지 않는다.
- 초대 메일과 소유권 이전 요청 메일에는 만료 기능을 제공하지 않는다.
- 만료 화면이나 만료 문구도 이번 범위에서 제공하지 않는다.

## 기능정의서 초안 반영 포인트

첨부된 기능정의서 초안은 아래 화면 단위로 구성되어 있다.

- `공유 드라이브`
  - 공유받은 항목 리스트
  - 빈 상태
  - 폴더 트리
  - 행 컨텍스트 메뉴
  - 공유 목록에서 제거 확인 모달
- `공유 모달`
  - 이메일 검색 입력 필드
  - 공유 대상 리스트
  - 공유 대상 더보기 메뉴
  - 사용자 삭제 모달
  - 권한 보유 사용자용 링크 복사
  - 모달 닫기
- `소유권 이전 확인 모달`
  - 소유권 이전 요청
  - 요청 성공/실패 토스트
- `이전 요청 취소 확인 모달`
  - 이전 요청 취소
  - 취소 성공/실패 토스트
- `노트 상세`
  - 공유 아이콘
  - 읽기 전용 표시
  - 소유권 이전 응답 모달
- `즐겨찾기`
  - 공유 항목 표시
- `내 드라이브`
  - 내가 공유한 항목 표시
- `삭제 확인 모달`
  - 공유 중 항목 삭제 경고

## 추가 논의 필요

### 폴더 공유 권한 전파 우선순위

- 폴더 공유 시 기존 하위 문서와 하위 폴더까지 포함한다.
- 공유 이후 새로 생성되는 하위 문서와 하위 폴더도 자동 공유한다.
- 아직 남은 논의는 하위 항목에 별도 공유 권한이 이미 있는 경우 폴더 공유 권한과 개별 공유 권한의 우선순위다.

### 공유 드라이브 메뉴 라벨 보정

- 공유 드라이브에서는 `공유 목록에서 제거`를 사용한다.
- 공유 모달의 대상자 메뉴와 사용자 삭제 모달에는 아직 `삭제`, `사용자 삭제` 표현이 남아 있다.
- 원본 항목 삭제와 혼동되지 않도록 `공유 해제`, `공유 대상에서 제거`, `공유 대상 삭제` 중 최종 라벨을 정하고 기능정의서에 반영해야 한다.

### 기능정의서/L10N 보정 필요

- `공개 링크` 관련 논의는 종료되었으므로 기능정의서에서는 공개 링크처럼 읽히는 표현을 피해야 한다.
- 링크 복사는 권한 보유 사용자용 공유 URL 복사로 설명해야 한다.
- `status.shareddrive.desc`는 status 계열 문구이므로 L10N type 정합성을 확인해야 한다.
- 공유 대상 삭제 또는 공유 해제 후 개인 태그와 즐겨찾기 즉시 삭제 정책을 기능정의서에 명시해야 한다.
- 폴더 공유 이후 새로 생성되는 하위 항목 자동 공유 정책을 기능정의서에 명시해야 한다.
- 소유권 이전 수락 시 기존 소유자가 일반 공유자로 강등되는 내용을 기능정의서에 명시해야 한다.
- 메일 링크 만료 기능 없음과 만료 화면 없음 정책을 기능정의서에 명시해야 한다.

## 후속 작업 제안

- 위 내용을 기준으로 `/spec-flow`를 실행하기 전에 `추가 논의 필요` 항목을 먼저 정리한다.
- 확정된 정책은 별도 `decisions/` 문서로 분리한다.
- 기능 정의 시 `공유 드라이브`, `공유 모달`, `소유권 이전`, `읽기 전용 표시`, `공유 중 삭제 경고`를 화면 단위로 분리해 작성한다.
- 공유 관련 기능은 읽기 전용 2차 범위와 이후 편집 권한 범위를 명확히 나누어 작성한다.
