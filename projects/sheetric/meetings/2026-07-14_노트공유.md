# 2026-07-14 노트공유 회의록

## 목적

Sheetric 2차 기능 범위 중 노트 공유와 공유 드라이브 관련 요구사항을 정리한다.

이 문서는 회의록이며, 확정 decision 문서가 아니다. 확정된 정책은 별도 `decisions/` 문서로 분리해 기록한다.

## 논의 내용

### 1. 노트 공유 기본 방향

- 2차 공유 기능은 우선 읽기 모드 중심으로 검토한다.
- 공유받은 문서와 폴더는 수정할 수 없다.
- 편집 권한 또는 실시간 공동 편집은 이후 단계에서 별도 검토한다.
- 사용자가 공유 문서를 보고 있다는 것을 알 수 있도록 어딘가에 읽기 모드 표시가 필요하다.

### 2. 공유 대상과 권한

- 특정 사용자를 지정해 공유할 수 있어야 한다.
- 특정 사용자 공유는 회원가입된 이메일만 가능해야 하며, 이메일 validation이 필요하다.
- 불특정 사용자 전체 공유 방식도 논의되었다.
- 현재 링크 공유 기능과의 관계를 정리해야 한다.
- 공유 해제 기능이 필요하다.

### 3. 공유 드라이브 표시 방식

- 이메일 초대 방식으로 공유받은 항목은 `공유 드라이브` 메뉴에 표시한다.
- 공유 드라이브에는 공유받은 문서와 폴더가 표시되어야 한다.
- 공유받은 문서 또는 폴더는 최신 업데이트 내용이 동기화되어야 한다.
- 공유 시점 이후 내용이 업데이트되면 사용자에게 업데이트가 있음을 표시해야 한다.
- 사용자가 확인한 뒤에는 업데이트 표시가 해제되는 확인 처리 기능이 필요하다.

### 4. 공유 드라이브 화면 구조

- 공유 드라이브 화면의 컨텍스트 메뉴는 일반 드라이브와 다르게 구성해야 한다.
- 생성 관련 메뉴는 공유 드라이브에서 숨기는 방향으로 논의되었다.
- 공유 드라이브 메인 화면 컬럼에는 `공유받은 날짜`, `최종 수정일` 표시가 필요하다.
- 공유 드라이브 메인 화면은 수정일 기준 정렬을 지원해야 한다.
- 표시 필드의 최종 기준은 `마지막 수정일`로 검토한다.
- 공유 드라이브 트리뷰는 우선 편집 불가 구조로 개발하고, 이후 개선한다.

### 5. 알림과 이메일

- 초대 공유 시 메일로 공유 내용을 알릴 필요가 있다.

### 6. 소유권 이전과 삭제

- 내가 만든 문서 또는 폴더를 다른 사람에게 소유권 이전할 수 있어야 한다.
- 내가 만든 문서 또는 폴더를 삭제할 때 공유 대상자에게 어떤 영향이 있는지 정책이 필요하다.

### 7. 기존 기능과의 연동

- 공유 폴더와 공유 문서에서도 즐겨찾기 기능이 유지되어야 한다.
- 즐겨찾기 목록에서 공유된 파일 또는 폴더는 별도 아이콘 등으로 구분 표시가 필요하다.
- 공유된 문서와 폴더에도 태그 기능을 그대로 사용할 수 있어야 한다.

## 추가 논의 필요

### 공유 범위와 접근 정책

- `불특정 사용자 전체 공유`가 현재 링크 공유와 같은 의미인지, 별도 공유 타입인지 정리 필요.
- 링크 공유 문서는 로그인 없이 접근 가능한지, 회원만 접근 가능한지 결정 필요.
- 읽기 전용 공유 URL과 기존 링크 공유 URL의 관계 정리 필요.

### 특정 사용자 공유

- 가입되지 않은 이메일을 입력했을 때 차단할지, 초대 플로우로 보낼지 결정 필요.
- 이메일 validation 실패 시 에러 문구와 표시 위치 결정 필요.
- 특정 사용자 공유의 권한 단위가 문서 단위인지, 폴더 단위인지, 폴더 하위 항목까지 포함하는지 확인 필요.

### 업데이트 표시와 확인 처리

- 업데이트 표시 기준을 항목 단위로 할지, 폴더 단위로 할지, 메뉴 배지로도 표시할지 결정 필요.
- `확인했음` 처리는 문서를 열면 자동 해제할지, 별도 확인 버튼이 필요한지 결정 필요.
- 최종 수정일과 업데이트 표시가 어떤 관계인지 정의 필요.

### 공유 해제

- 공유 해제 시 공유 드라이브에서 즉시 제거되는지 결정 필요.
- 링크 공유와 특정 사용자 공유가 동시에 걸린 경우 해제 우선순위 필요.
- 공유 해제 알림 메일 또는 화면 알림이 필요한지 결정 필요.

### 소유권 이전과 삭제

- 소유권 이전 후 기존 소유자의 권한이 어떻게 바뀌는지 결정 필요.
- 폴더 소유권 이전 시 하위 문서와 하위 폴더까지 함께 이전되는지 결정 필요.
- 소유자가 공유 중인 문서 또는 폴더를 삭제할 때 공유받은 사용자의 접근이 어떻게 되는지 결정 필요.
- 삭제 전 소유권 이전을 유도할지 여부 결정 필요.

### 공유 드라이브 컨텍스트 메뉴

- 공유 드라이브에서 허용할 액션 목록 정의 필요.
- 생성, 업로드, 삭제, 이동, 이름 변경, 태그, 즐겨찾기, 링크 복사 중 어떤 액션을 숨기거나 비활성화할지 결정 필요.

### 태그와 즐겨찾기

- 공유받은 항목에 붙인 태그가 개인 태그인지, 원본 소유자와 공유되는 태그인지 결정 필요.
- 공유받은 항목을 즐겨찾기했을 때 내 즐겨찾기 목록에서만 보이는지 결정 필요.

### 이메일 알림

- 초대 메일 제목, 본문, 발신자, 링크 만료 여부 결정 필요.
- 공유 해제, 소유권 이전, 업데이트 발생 시 이메일 알림도 필요한지 결정 필요.

## 후속 작업 제안

- 위 논의 내용을 기준으로 `/spec-flow`를 실행하기 전에 미확정 항목을 확인한다.
- 확정된 정책은 별도 `decisions/` 문서로 분리한다.
- 기능 정의 시 `공유 드라이브`, `노트 공유`, `소유권 이전`, `공유 알림`을 별도 기능 또는 섹션으로 분리할지 검토한다.
- 공유 관련 기능은 읽기 전용 1차 범위와 이후 편집 권한 범위를 명확히 나누어 작성한다.
