# 2026-07-14 회의록 + 기획팀 결정사항

## 목적

Sheetric 2차 기능 범위 중 노트 공유와 공유 드라이브 관련 회의 내용과, 이후 기획팀에서 보정한 결정사항을 분리해 기록한다.

이 문서는 회의록과 기획 정리 문서이며, 확정 decision 문서가 아니다. 확정된 정책은 별도 `decisions/` 문서로 분리해 기록한다.

## 관련 자료

- `Sheetric 프로젝트 - 기능정의_2차.tsv`
- `Sheetric 프로젝트 - L10N.tsv`
- `Sheetric 프로젝트 - 기능정의_2차_공유드라이브.tsv` (공유 드라이브 2차 기능정의서 초안, 확정본 아님)

## 원래 회의록

### 노트 공유 기능

- 모든 공유는 우선 읽기 모드로 제공한다.
- 편집 권한은 이후 단계에서 검토한다.
- 공유받은 문서에서는 읽기 모드임을 표시해야 한다.
- 특정 사용자 지정 공유가 필요하다.
- 초대 공유 시 이메일로 공유 내용을 알린다.
- 현재 링크 공유 기능과 공유 URL 정책을 정리해야 한다.
- 이메일 초대로 공유받은 항목은 `공유 드라이브` 메뉴에 표시한다.
- 공유 문서는 최신 업데이트 내용이 동기화되어야 한다.
- 공유 시점 이후 내용이 업데이트되었음을 표시하고, 확인 후 표시를 해제하는 기능이 필요할 수 있다.
- 공유 해제 기능이 필요하다.
- 소유권 이전 기능이 필요하다.
- 내가 만든 문서나 폴더를 다른 사람에게 이전할 수 있어야 한다.
- 공유 폴더와 공유 문서의 즐겨찾기 기능은 유지한다.
- 즐겨찾기 목록에서 공유된 파일이나 폴더는 별도 아이콘 등으로 구분한다.
- 공유받은 문서는 수정할 수 없다.
- 실시간 편집 기능은 이후 단계에서 검토한다.
- 태그 기능은 공유된 문서와 폴더에도 그대로 사용할 수 있어야 한다.
- `공유 드라이브` 화면에서는 컨텍스트 메뉴를 공유받은 항목에 맞게 변경한다.
- `공유 드라이브`에서는 생성 관련 메뉴를 숨긴다.
- `공유 드라이브` 메인 화면 컬럼에는 공유받은 날짜와 최종 수정일을 표시한다.
- `공유 드라이브` 메인 화면은 수정일 기준으로 정렬한다.
- `공유 드라이브` 트리뷰는 우선 편집 불가로 개발한다.

## 이후 기획팀 결정사항

### 공유 범위와 접근 정책

- 공개 링크 공유는 제공하지 않는다.
- 공유 대상자는 반드시 가입 및 로그인된 사용자여야 한다.
- 노트가 열린 상태의 일반 URL과 공유를 통해 접근하는 URL은 서로 다르다.
- 일반 URL로 권한 없는 사용자가 접근하면 기존처럼 접근 오류를 노출한다.
  - 기능정의서/L10N: `toast.wrongapproach.error`
- 공유 모달에서 복사되는 링크는 공개 링크가 아니라 권한 보유 사용자용 공유 URL이다.
- 공개 링크 ON/OFF, 공개 링크 재생성, 공개 링크 폐기 기능은 이번 범위에서 다루지 않는다.
- 기존 `공유 링크 별도 읽기 전용 URL` 결정 중 "편집 URL과 공유 URL을 분리한다"는 방향은 유지하되, 접근 대상은 로그인된 권한 보유 사용자로 제한한다.
- 기존 `폴더 공유 제외` 결정은 `상태: 삭제`이므로, 이번 2차 범위에서는 폴더 공유를 포함해 검토한다.

### 특정 사용자 공유

- 회원가입된 사용자명과 이메일만 검색하고 선택할 수 있다.
- 이메일 입력 후 Enter 또는 검색 결과 선택 시 유효성 검사를 수행한다.
- 유효성 검사를 통과한 이메일은 X 버튼이 있는 chip 형태로 전환된다.
- 가입되지 않은 이메일은 초대 플로우로 넘기지 않고 실패 토스트를 노출한다.
  - 기능정의서/L10N: `toast.emailnotregistered.error`
- 본인 이메일은 공유 대상으로 추가할 수 없다.
  - 기능정의서/L10N: `toast.selfinvite.error`
- 이미 공유된 사용자는 검색 결과에서 제외한다.
- chip의 X 버튼을 클릭하면 API 호출 없이 전송 전 chip만 제거한다.
- `[초대]` 버튼은 chip이 1개 이상 있을 때만 활성화한다.
- `[초대]` 클릭 시 현재 남아있는 chip을 공유 대상 추가 API로 일괄 요청한다.
- 전체 성공 시 공유 대상 리스트에 전원 추가하고 chip을 초기화한다.
  - 기능정의서/L10N: `toast.shareadded.success`
- 일부 실패 시 성공한 이메일은 리스트에 반영하고, 실패한 이메일은 chip으로 남긴다.
  - 기능정의서/L10N: `toast.shareadd.error`
- 사용자 추가, 공유 해제, 소유권 이전 요청 등은 각 액션 실행 시 즉시 저장된다.
- 공유 모달 닫기는 저장 또는 취소 역할을 하지 않는다.
- 모달을 닫아도 이미 성공한 변경사항은 유지된다.

### 폴더 공유 권한 전파

- 폴더를 공유하면 폴더 안의 기존 하위 노트와 하위 폴더도 같은 사용자에게 공유된다.
- 공유 이후 해당 폴더 안에 새로 생성되는 하위 노트와 하위 폴더도 자동 공유된다.
- 폴더 공유로 포함된 사용자도 하위 노트와 하위 폴더의 공유 대상 리스트에 표시한다.
- 하위 노트나 하위 폴더에서 사용자를 삭제하면 해당 항목에서만 접근 권한이 제외된다.
- 하위 항목에서 사용자를 삭제해도 상위 폴더의 공유 대상 리스트에서는 제거되지 않는다.
- 공유 드라이브 항목은 내 드라이브나 다른 폴더로 이동할 수 없다.

### 공유 드라이브 표시 방식

- 이메일 초대 방식으로 공유받은 항목은 `공유 드라이브` 메뉴에 표시한다.
- 공유 드라이브에는 공유받은 노트와 폴더가 표시된다.
- 공유 드라이브 목록 테이블 컬럼은 아래와 같다.
  - 체크박스
  - 즐겨찾기
  - 이름
  - 소유자
  - 크기
  - 공유일
  - 수정일
- 기본 정렬은 수정일 기준으로 한다.
- 브라우저 가로 폭이 축소되면 소유자, 크기, 공유일, 수정일 순서로 컬럼을 숨긴다.
- 공유받은 항목이 없으면 빈 상태 문구를 노출한다.
  - 기능정의서/L10N: `status.shareddrive.desc`
- 공유 드라이브 트리뷰는 우선 편집 불가로 개발한다.
- 트리뷰에서는 폴더 펼침, 접힘, 하위 폴더 진입만 가능하다.
- 이름 변경, 이동 등 편집성 기능은 제공하지 않는다.
- 업데이트 표시와 확인 처리 기능은 이번 범위에서 스펙아웃한다.

### 공유 드라이브 컨텍스트 메뉴

- 공유 드라이브에서는 생성, 업로드, 이동, 이름 변경 등 소유자 편집 액션을 숨기거나 제공하지 않는다.
- 공유 드라이브 항목 컨텍스트 메뉴에서 허용할 액션은 아래와 같다.
  - 공유
  - 즐겨찾기
  - 다운로드
  - 태그 관리
  - 속성
  - 공유 목록에서 삭제
- 공유 액션은 소유자와 초대된 사용자 모두에게 노출한다.
- 초대된 사용자도 다른 사용자를 추가하거나 삭제할 수 있다.
- 단, 소유권 이전은 소유자 전용 액션이다.
- 다운로드는 권한이 있는 로그인 사용자에게만 허용한다.
- `공유 목록에서 삭제`를 실행하면 본인의 접근 권한을 제거하고 공유 드라이브 목록에서 즉시 제거한다.
- 공유 목록에서 삭제 성공 시 해당 항목의 개인 태그와 즐겨찾기 참조도 즉시 삭제한다.
- 공유 목록에서 삭제가 처리되면 소유자 쪽 공유 모달의 공유 대상 리스트에서도 해당 사용자를 함께 제거한다.
  - 기능정의서/L10N: `toast.sharingleft.success`
  - 기능정의서/L10N: `toast.sharingleft.error`

### 공유 모달과 공유 대상 리스트

- 노트 상세의 기존 링크 복사 진입점은 공유 모달 오픈 진입점으로 변경한다.
- 공유 모달 타이틀은 `공유`로 표시한다.
- 소유자 본인 행은 `소유자` 텍스트를 고정 표시하고 편집할 수 없다.
- 공유 대상 리스트에는 현재 항목에 접근 가능한 사용자를 표시한다.
- 폴더 공유로 포함된 사용자도 하위 노트와 하위 폴더의 공유 대상 리스트에 표시한다.
- 공유 대상 행에는 더보기 메뉴를 노출한다.
- 더보기 메뉴의 내용은 보는 사람이 소유자인지 초대된 사용자인지에 따라 다르다.
- 소유자가 일반 공유 대상 행을 볼 때 제공하는 메뉴는 아래와 같다.
  - 소유권 이전
  - 삭제
- 초대된 사용자가 일반 공유 대상 행을 볼 때 제공하는 메뉴는 아래와 같다.
  - 삭제
- 초대된 사용자는 소유권 이전 메뉴를 볼 수 없다.
- 소유권 이전 요청 대기 중인 대상자의 더보기 메뉴는 소유자에게만 대기 상태를 노출한다.
- 공유 대상 삭제 메뉴를 클릭하면 `사용자 삭제` 확인 모달을 노출한다.
- 사용자 삭제 성공 시 공유 대상 리스트에서 해당 사용자를 즉시 제거한다.
- 사용자 삭제 성공 시 해당 사용자의 공유 드라이브, 개인 태그, 즐겨찾기 참조도 즉시 삭제한다.
  - 기능정의서/L10N: `toast.usershareremoved.success`
  - 기능정의서/L10N: `toast.usershareremove.error`
- 링크 복사 성공 시 완료 토스트를 노출한다.
  - 기능정의서/L10N: `toast.linkcopied.success`

### 소유권 이전

- 내가 만든 노트 또는 폴더를 다른 사람에게 소유권 이전할 수 있어야 한다.
- 소유권 이전은 요청을 보낸 뒤 대상자가 노트 상세 화면에서 수락하거나 거절한다.
- 소유권 이전 요청 성공 시 대상자에게 이메일을 발송한다.
  - 기능정의서/L10N: `toast.ownershiptransferrequested.success`
- 소유권 이전 요청 실패 시 실패 토스트를 노출한다.
  - 기능정의서/L10N: `toast.ownershiptransferrequest.error`
- 소유권 이전 요청 취소 성공/실패 토스트를 노출한다.
  - 기능정의서/L10N: `toast.ownershiptransfercanceled.success`
  - 기능정의서/L10N: `toast.ownershiptransfercancel.error`
- 메일에는 `확인하기` 버튼을 포함하며, 클릭 시 해당 노트 상세 화면으로 이동한다.
- 실제 수락/거절 처리는 메일 링크 자체가 아니라 노트 상세 화면에 자동으로 뜨는 모달에서 이루어진다.
- 대상자가 노트 상세 화면에 진입했을 때 대기 중인 소유권 이전 요청이 있으면 응답 모달을 자동 오픈한다.
- 대상자가 수락하면 수락과 동시에 소유권이 전환된다.
  - 기능정의서/L10N: `toast.ownershiptransferaccepted.success`
  - 기능정의서/L10N: `toast.ownershiptransferaccept.error`
- 소유권 이전 후 기존 소유자는 일반 공유자로 전환된다.
- 대상자가 거절하면 기존 소유자에게 거절 안내 메일을 발송한다.
  - 기능정의서/L10N: `toast.ownershiptransferdeclined.success`
  - 기능정의서/L10N: `toast.ownershiptransferdecline.error`
- 폴더 소유권 이전 시 하위 노트와 하위 폴더까지 함께 이전한다.
- 폴더 소유권 이전 확정 시 하위 노트나 하위 폴더에 걸려 있던 개별 소유권 이전 요청은 자동 취소한다.
- 소유권 이전 요청 대상자가 탈퇴하면 이전 요청을 자동 취소하고 기존 소유자에게 안내 이메일을 발송한다.

### 소유자가 공유 중인 항목을 삭제하는 경우

- 내가 만든 노트나 폴더를 삭제하면 공유받은 사용자의 공유 드라이브 목록에서 즉시 제거한다.
- 삭제 성공 시 공유 대상자의 개인 태그와 즐겨찾기 참조도 즉시 삭제한다.
- 공유 중인 항목 삭제 시 소유권 이전을 유도하지 않고 경고 모달만 노출한다.
- 공유받은 사용자가 소유자에 의해 휴지통으로 이동된 노트에 진입하면 `삭제 예정 안내` 모달을 자동 오픈한다.
- 삭제 예정 안내 모달에서는 사본 만들기 액션을 제공한다.
- 사본은 원본과 공유 관계를 승계하지 않는 독립 문서로 생성한다.
  - 기능정의서/L10N: `toast.duplicated.success`
  - 기능정의서/L10N: `toast.duplicate.error`

### 태그와 즐겨찾기

- 공유받은 항목에도 태그 기능을 사용할 수 있다.
- 공유받은 항목에 붙인 태그는 개인 태그다.
- 공유받은 항목을 즐겨찾기하면 내 즐겨찾기 목록에서만 보인다.
- 즐겨찾기 목록에서 내가 공유했거나 공유받은 항목은 이름 옆에 공유 아이콘으로 구분한다.
- 즐겨찾기 목록의 소유자 컬럼은 본인 소유는 `나`, 타인 소유는 소유자 이름으로 표시한다.
- 내 드라이브에서 내가 다른 사용자에게 공유한 항목도 이름 옆에 공유 아이콘을 표시한다.

### 이메일 알림

- 초대 공유 시 이메일로 공유 내용을 알린다.
- 공유 알림 메일에는 노트일 경우 `노트 열기`, 폴더일 경우 `폴더 열기` 버튼을 제공한다.
- 소유권 이전 요청 메일에는 `확인하기` 버튼을 제공한다.
- 소유권 이전 거절 안내 메일에는 노트일 경우 `노트 열기`, 폴더일 경우 `폴더 열기` 버튼을 제공한다.
- 소유권 이전 자동 취소 안내 메일에도 노트일 경우 `노트 열기`, 폴더일 경우 `폴더 열기` 버튼을 제공한다.
- 공유 해제 시 이메일 알림은 보내지 않는다.
- 소유권 이전 요청 시 이메일 알림은 보낸다.
- 소유권 이전 거절 시 기존 소유자에게 거절 안내 메일을 보낸다.
- 소유권 이전 요청 대상자 탈퇴로 요청이 자동 취소되면 기존 소유자에게 자동 취소 안내 메일을 보낸다.
- 업데이트 발생 시 이메일 알림은 보내지 않는다.
- 초대 메일과 소유권 이전 요청 메일에는 만료 기능을 제공하지 않는다.
- 만료 화면이나 만료 문구도 이번 범위에서 제공하지 않는다.

## 기능정의서 초안 반영 포인트

첨부된 공유 드라이브 기능정의서 초안은 아래 화면 단위로 구성되어 있다.

- `공유 드라이브`
  - 공유받은 항목 리스트
  - 빈 상태
  - 폴더 트리
  - 행 컨텍스트 메뉴
  - 공유 목록에서 삭제 확인 모달
- `공유 모달`
  - 이메일 검색 입력 필드
  - 검색 팝오버
  - 공유 대상 리스트
  - 공유 대상 더보기 메뉴
  - 사용자 삭제 모달
  - 권한 보유 사용자용 링크 복사
  - 모달 닫기
- `소유권 이전 확인 모달`
  - 소유권 이전 요청
  - 대상자 탈퇴로 인한 자동 취소
- `이전 요청 취소 확인 모달`
  - 이전 요청 취소
- `노트 상세`
  - 공유 아이콘
  - 읽기 전용 표시
  - 소유권 이전 응답 모달
  - 삭제 예정 안내 모달
- `즐겨찾기`
  - 공유 항목 표시
- `내 드라이브`
  - 내가 공유한 항목 표시
- `공유 알림 이메일`
  - 노트/폴더 공유 알림 버튼
- `소유권 이전 요청 이메일`
  - 소유권 이전 요청 버튼
- `소유권 이전 거절 안내 이메일`
  - 거절 안내 버튼
- `소유권 이전 자동 취소 안내 이메일`
  - 자동 취소 안내 버튼

## 추가 논의 필요

### 하위 항목 개별 제외와 재공유 정책

- 폴더 공유로 포함된 사용자를 하위 노트나 하위 폴더에서 삭제하면 해당 항목에서만 접근 권한이 제외된다.
- 추가로 정해야 할 부분은 이후 상위 폴더의 공유 대상 변경, 동일 사용자 재초대, 새 하위 항목 생성 시 이 개별 제외 상태를 유지할지 초기화할지이다.

### 중복 공유 권한 표시와 정렬

- 같은 사용자가 상위 폴더 공유와 하위 항목 공유를 동시에 갖는 경우 공유 대상 리스트에는 한 번만 표시하는 방향이 자연스럽다.
- 다만 소유자, 일반 공유자, 소유권 이전 대기중 사용자, 폴더 공유로 포함된 사용자가 함께 있을 때 리스트 정렬 우선순위는 별도 확정이 필요하다.

### 영구 삭제 이후 접근 실패 처리

- 기능정의서 초안에는 휴지통 이동 상태에서 공유받은 사용자가 노트에 진입했을 때 `삭제 예정 안내` 모달과 사본 만들기를 제공하는 흐름이 있다.
- 아직 남은 논의는 원본이 영구 삭제된 이후 기존 공유 URL, 즐겨찾기, 태그 필터 잔여 접근에서 어떤 화면 또는 토스트를 보여줄지이다.

## 후속 작업 제안

- 확정본 기능정의서로 정리할 때 위 `추가 논의 필요` 항목을 먼저 확정한다.
- 확정된 정책은 별도 `decisions/` 문서로 분리한다.
- `/spec-flow` 실행 시 `공유 드라이브`, `공유 모달`, `소유권 이전`, `읽기 전용 표시`, `삭제 예정 안내`, `이메일 알림`을 화면 단위로 분리해 작성한다.
- 공유 관련 기능은 읽기 전용 2차 범위와 이후 편집 권한 범위를 명확히 나누어 작성한다.
