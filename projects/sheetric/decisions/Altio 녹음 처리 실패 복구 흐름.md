# Altio 녹음 처리 실패 복구 흐름

## 상태
추가

## 날짜
2026-09-21

## 프로젝트
- Sheetric

## 결정
- 녹음 종료 또는 녹음 파일 업로드 완료 이후 처리를 `녹음 파일 업로드` → `스크립트 변환 및 요약 생성` 두 단계로 분리한다.
- 각 단계는 노트 본문 내 블록 형태(업로드 중, 업로드 실패, 생성 중, 생성 실패)로 진행 상태를 노출한다.
- 녹음 파일 업로드가 실패하면 실패 상태를 블록 내에 유지하고, 임시 녹음 파일과 블록을 삭제하지 않는다.
- 업로드 실패 블록에는 [다시 시도하기] 버튼을 노출한다. 클릭 시 최초 진입 방식에 따라 이전 단계 UI를 재노출한다.
  - [Altio 녹음]으로 시작한 경우: 녹음 블록을 재노출해 재녹음한다.
  - [Altio 녹음 업로드]로 시작한 경우: 파일 업로드 블록을 재노출해 재업로드한다.
- 스크립트 변환 및 요약 생성이 실패하면 실패 상태를 블록 내에 유지하고, 이미 업로드된 녹음 파일은 보존한다.
- 생성 실패 블록의 [다시 시도하기] 클릭 시에는 업로드된 녹음 파일을 그대로 사용해 생성만 재시도하며, 녹음이나 업로드 단계로 되돌아가지 않는다.
- 업로드 실패와 생성 실패 모두 자동 재시도 없이 사용자의 수동 재시도로만 재처리한다.

## 이유
- 기존에는 녹음 종료 후 스크립트 변환·요약 생성에 실패하면 오류 토스트만 노출되고 녹음 파일과 블록이 함께 사라져, 사용자가 녹음 내용을 복구하거나 다시 분석할 수 없었다.
- 업로드 실패와 생성 실패는 원인이 다르므로(전송 문제 vs 처리 문제) 실패한 단계에 맞는 재시도 경로를 제공해야 불필요한 재작업(재녹음)을 막을 수 있다.
- 생성 실패 시 이미 업로드된 파일을 재사용해야 사용자가 같은 파일을 다시 첨부하거나 재녹음하지 않아도 된다.
