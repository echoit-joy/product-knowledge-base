# 다중 선택 시 컨텍스트 메뉴 구성 및 공유 노출 조건

## 상태
추가

## 날짜
2026-09-09

## 프로젝트
- Sheetric

## 결정
- 체크박스로 파일/폴더/노트를 2개 이상 선택한 상태에서 더보기(⋮) 또는 우클릭 시 노출되는 컨텍스트 메뉴 구성을 확정한다.
- 대상 화면: MainPage, 내 드라이브, 즐겨찾기, 노트(폴더트리)
  - 구성: 공유 | 즐겨찾기 설정 | 복사하기 | 아카이브 | 다운로드 ─── 항목 이동 | AI 검색 설정 ─── 삭제
- 대상 화면: 공유 드라이브 (다중 선택 가능)
  - 구성: 공유 | 즐겨찾기 설정 | 복사하기 | 다운로드 ─── 항목 이동 ─── 삭제
- 공통: 이름 바꾸기, 태그 관리, 속성은 단일 항목 전용 기능이므로 다중 선택 시 메뉴에서 제외한다.
  - 태그 관리는 AI 추천 태그 기능과 연동되어 있어 다중 선택 대상에서 완전히 제외한다.
- [공유] 항목은 선택된 모든 항목의 공유 상태가 완전히 동일한 경우에만 노출한다.
  - 공개/비공개 상태가 모두 동일해야 함
  - 초대된 사용자·그룹 목록이 완전히 동일해야 함 (초대 대기중 상태 포함)
  - 소유자가 동일해야 함
  - 소유권 이전 상태가 동일해야 함 (이전 진행중·대기중·취소 등 상태 포함)
  - 하나라도 불일치하면 [공유] 항목만 미노출(비활성)되고 나머지 메뉴는 그대로 노출
- 다중 선택(2개 이상 항목)으로 공유 모달에 진입한 경우, 모달 하단의 [링크 복사] 버튼은 비활성화한다 (노출은 유지, 클릭만 불가).
  - 여러 항목의 공유 링크를 하나로 복사할 수 없으므로 항상 비활성화 처리
  - 공개/비공개 토글은 선택된 항목 전체에 동일하게 적용
- 변경 없음: 휴지통, 아카이브 화면의 다중 선택 메뉴는 공유 대상이 아니므로 이번 결정 범위에서 제외

## 이유
- 다중 선택 시 컨텍스트 메뉴 구성이 기능정의서에 별도로 정의돼 있지 않아 발생한 스펙 공백을 메우기 위함.
- 이름 바꾸기·속성·태그 관리는 단일 항목 기준으로 설계된 기능이라 다중 선택 시 의미가 없거나(이름 바꾸기·속성) AI 추천 로직과 충돌(태그 관리)하므로 제외.
- 공유 상태가 다른 항목들을 한 번에 공유 처리하면 사용자가 의도하지 않은 권한 변경이 발생할 수 있어, 공유 상태가 완전히 동일한 경우로만 제한.
- 개발자 질문(소유자·소유권 이전 상태가 다른 항목의 [공유] 노출 여부)에 대해, 소유자·소유권 이전 상태도 공유 상태의 일부로 보고 동일 조건에 포함하기로 확정.
- 링크 복사는 항목 1개당 URL이 1개씩 존재해 다중 선택 시 대표 링크를 정할 수 없으므로 항상 비활성화 처리 (버튼 자체는 유지해 존재는 인지시키되 동작만 막음).
