# 디폴트 문서 생성일·수정일 미노출

## 상태
수정

## 날짜
2026-09-04

## 프로젝트
- Sheetric

## 결정
- 회원가입 직후 생성되는 디폴트 문서는 사용자가 최초로 수정하기 전까지 생성일/수정일을 노출하지 않는다.
- 사용자가 디폴트 문서를 최초로 수정한 시점부터, 그 시점을 기준으로 수정일을 노출한다.
- 최초 수정 전 디폴트 문서의 날짜 표시는 화면 유형별로 아래와 같이 적용한다.
  - Main Page 즐겨찾기 카드 및 각 메뉴(즐겨찾기·내 드라이브·공유 드라이브)의 테이블: 생성일/수정일 칸을 빈칸으로 노출
  - 속성 모달: 생성일/수정일을 `-`로 노출
- 적용 대상 화면과 컬럼은 아래와 같다.
  - MainPage: 즐겨찾기 미리보기 섹션·최근 작업 섹션의 생성일/수정일, 속성모달
  - 즐겨찾기: 수정일, 속성모달
  - 내 드라이브: 생성일/수정일, 속성모달
  - 공유 드라이브: 수정일, 속성모달

## 이유
- 회원가입 시점은 사용자의 실제 작성·편집 행위가 아니므로, 이를 생성일/수정일로 노출하면 사용자가 해당 시점에 문서를 작성·수정한 것처럼 오인할 수 있다.
- 기존 [항목 생성·수정 시점 정책](../features/feature-index.md)(신규 노트는 수정일을 생성일과 동일하게 초기화)은 사용자가 직접 만든 일반 노트를 전제로 한 규칙이며, 회원가입 시 시스템이 자동 제공하는 디폴트 문서에는 그대로 적용되지 않는다.
- 현재는 회원가입 시점을 기준으로 생성일/수정일이 모든 화면에 노출되고 있어(QA 접수 대상), 실제 사용자 행위가 없었음에도 이력이 있는 것처럼 보이는 문제가 있다.
