# 공유 항목 접근 및 속성 표시 기준

## 상태
수정

## 날짜
2026-09-11, 2026-09-14, 2026-09-16

## 프로젝트
- Sheetric

## 결정
- 초대받은 사용자가 로그인 상태에서 공유 메일의 열기 버튼을 클릭하면 공유받은 항목 유형에 맞는 상세 화면으로 이동한다.
- 초대받은 사용자가 비회원인 경우에도 회원가입 또는 로그인 완료 후 초대 이메일과 계정 이메일이 일치하면 해당 공유 항목으로 자동 진입한다.
- 공유받은 노트로 이동할 때는 해당 노트 탭이 열린 상태로 진입한다.
- 읽기 전용 공유 노트 화면에서도 상단 공유 버튼을 제공하며, 기존 공유 링크 복사 동작과 동일하게 동작한다.
- 비회원이 초대 링크로 접근해 항목 확인 모달을 보는 경우, 모달 뒤에는 로그인 화면이 아니라 빈 배경을 노출한다.
- 원 소유자가 휴지통으로 이동한 공유 노트에 접근하면 노트 상세 화면에 진입한 뒤 삭제 예정 안내 모달을 노출한다. 폴더는 테이블 화면에서 삭제 예정 안내 모달을 노출한다.
- 공유 드라이브의 노트·폴더 속성 모달에는 실제 위치를 공유 드라이브로 표시하고, 공유일을 함께 노출한다.
- 공유 초대 검색 결과에는 소유자와 이미 접근 권한이 있는 사용자를 노출하지 않는다.
- 공유 초대 검색 팝오버가 열리면 첫 번째 검색 결과를 기본 선택 상태로 둔다.
- 기본 선택된 공유 초대 검색 결과에서 Enter를 입력하면 해당 사용자를 입력 필드에 chip 형태로 추가하고, 사용자 이름 일부가 텍스트로 남지 않아야 한다.
- Read-only 권한으로 공유 노트에 접근한 사용자는 다른 사용자의 협업 커서를 보지 않는다.
- 공유 문서의 수정 내용은 초대자 측 화면에도 지연 없이 동기화되어야 한다.
- 삭제 예정 공유 항목의 사본을 만들면 생성된 사본은 사용자의 내 드라이브 테이블과 폴더 트리에 바로 노출한다.
- 닉네임이나 프로필 이미지 변경, 폴더 공유로 인한 하위 항목 공유 상태 변경은 새로고침이나 재로그인 없이 관련 테이블의 소유자 정보와 공유 아이콘에 반영한다.
- 공유 드라이브에서 공유받은 파일을 표시할 때 파일의 `수정일` 항목은 노출하지 않는다.

## 이유
- 공유 진입 경로는 이메일, 공개 링크, 공유 드라이브 등 여러 경로가 있어 사용자가 같은 항목으로 예측 가능하게 도착해야 한다.
- 공유 속성과 초대 검색 결과는 실제 권한 상태를 반영해야 중복 초대나 잘못된 위치 표시를 줄일 수 있다.
- 키보드로 사용자를 빠르게 추가할 수 있어야 하며, 검색어 입력과 결과 선택 동작이 서로 섞이면 잘못된 chip이 만들어질 수 있다.
- Read-only 사용자는 편집 협업 상태에 참여하지 않으므로 협업 커서를 노출하지 않는 것이 권한 모델과 일치한다.
- 파일 수정일은 소유자 화면에서도 제공하지 않는 정보이므로 공유받은 파일에도 노출하지 않는다.
